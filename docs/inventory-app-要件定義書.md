# 棚卸しアプリ 要件定義書（確定版）

最終更新: 2026-07-07
ステータス: **プロトタイプ実装済み**（`inventory-app/` ディレクトリ、ローカルExcelモードで動作確認済み）

## 1. 目的

紙で行っている棚卸し作業を、スマホで完結できるWebアプリに置き換える。
最終的なデータはExcelで扱えることが必須条件。

## 2. 前提条件

- 利用環境: 基本的にネットワークにつながる（工場内Wi-Fiなど）→ オフライン対応は不要
- 利用人数: 複数人で使うが、**同時アクセスはしない**（交代制で使う想定）
  → 排他制御・リアルタイム同期の作り込みは不要。都度最新データを読み込む形でOK
- 品目マスタ: 既存の実地棚卸表Excel（.xlsm）からインポート済み（→ §5-1）

## 3. データの持たせ方（決定）

**Teamsの棚卸し専用チーム（新規作成）に置いたExcelファイルを共有DB代わりに使う。**

- 棚卸し専用のTeamsチームを新規作成し、そこにExcelファイルを1つアップロードする
- アプリは Microsoft Graph API（アプリケーション権限）経由でこのファイルを読み書きする
- 棚卸し終了後はこのExcelファイルをそのままダウンロード／共有すればよい（変換不要）
- 特別なアクセス制限の作り込みは不要（機密情報ではないため）

### Excelファイルの構成（実装済み・`inventory-app/data/inventory.xlsx` が雛形）

| シート | テーブル名 | 列 |
|---|---|---|
| 品目マスタ | `MasterTable` | 品目ID / 原料コード / 品名 / カテゴリ / 単位 / 備考 |
| 棚卸し記録 | `RecordTable` | 記録ID / 記録日時 / 棚卸し月 / 原料コード / 品名 / カテゴリ / 数量 / 単位 / 半端量 / 期限切れ量 / 期限切れ日 / 保管場所 / 期限日 / 期限区分 / 入力者 / 備考 |
| 入力者 | `MemberTable` | 名前 |

- アプリはテーブル名（MasterTable等）を頼りに読み書きするため、**シート名・列構成・テーブル名は変更しないこと**（行の追加・値の編集は自由）
- 「入力者」シートに名前を追加すれば、アプリの入力者選択肢に反映される
- 単位はスラッシュ区切りで複数指定可（例: `箱/本` → アプリで切替ボタンになる）
- `棚卸し月`（例: 2026-07）は自動記録され、Excel側で月別フィルタに使える

（検討したが不採用の案: Googleスプレッドシート共有DB案 → 会社がGoogleアカウントの業務利用を承認しない可能性があるため見送り）

## 4. 認証・ログイン（決定）

- **当面: 共通PINコード方式**（環境変数 `APP_PIN` で設定。認証後30日間有効なCookieを発行）
- **入力者の記録**: PIN認証後に「名前を選択」してから入力する方式。全記録に入力者名が残るため、将来の個人ログイン（個人PIN等）への移行が容易
- 現場の人が個別にMicrosoftアカウントでログインする必要はない。Excelへのアクセスは、Azure ADに登録したアプリのアプリケーション権限（サービスプリンシパル）でサーバー側が行う

## 5. 機能要件（実装済み）

### 5-1. 品目マスタ管理
- 既存の実地棚卸表（.xlsm）から `inventory-app/scripts/import_master.py` でインポート済み: **139品目**（原料豆38 / 副原料87 / フィルター14）
- **原料コードについて（決定変更）**: 提供されたExcelに原料コードが**ほぼ含まれていた**（原料豆36/38件・副原料82/87件）ため、**初期リリースから原料コードを品目マスタに取込済み**。フィルター等コードが無い品目は空欄とし、後日Excel上で直接追記できる
- ふりがな（Excelのphonetic情報）は品名から自動除去済み
- 品目の追加・修正はTeams上のExcelの「品目マスタ」シートを直接編集すればよい

### 5-2. 棚卸し入力
- 品名検索: インクリメンタル検索（ひらがな⇔カタカナ・半角⇔全角を自動吸収。例:「ふぃるたー」で「天然水ﾌｨﾙﾀｰ」がヒット）＋カテゴリ絞り込みチップ
- マスタにない品目は手入力で登録可能
- 数量入力: ＋／−ボタンとテンキー（decimal）の両対応。複数単位の品目（箱/本）は単位切替ボタン
- **半端量（副原料のみ）**: 数量には半端を含んだ合計をそのまま入力し、半端量には「そのうち何kgが端数（開封済み等）か」を内訳メモとして記入する（合計の再計算はしない）
- **期限切れ別枠（原料豆・副原料）**: 期限切れ分は数量に含めず、期限切れ量と期限切れ日を別枠で入力する（紙棚卸表の「期限切れ※合計に含まない・期限も記入」列と同じ運用）
- 保管場所（任意）
- **期限情報（追加決定）**: 既存棚卸表の「期限切れ・来月期限・再来月期限」運用を引き継ぎ、**期限日（任意）＋期限区分**を入力可能。期限日を入れると期限区分は自動判定される（今月以前→期限切れ / 来月→来月期限 / 再来月→再来月期限 / それ以降→空欄。月末実地棚卸し基準・手動変更可）
- 備考（任意）
- 入力者（名前選択・端末に記憶）
- 登録すると「棚卸し記録」シートに1行追記される

### 5-3. 一覧・確認・編集
- 記録の一覧（月別グループ・新しい順）、タップで編集・削除
- 「最新を取得」ボタンで都度シートから再読込（別の人が別タイミングで使うケースに対応）

### 5-4. データ出力
- Teams上のExcelファイルの実体がそのまま最終データ（変換不要）
- 保険としてCSVエクスポートボタンあり（UTF-8 BOM付き・Excelでそのまま開ける）

## 6. 非機能要件（実装済み）

- スマホブラウザ前提のレスポンシブUI（PC でも利用可）
- ネットワーク接続前提（オフラインキャッシュなし）
- リアルタイム同期・排他制御なし（都度読み込み）
- データ層は抽象化されており、環境変数 `STORE_MODE` で切替:
  - `local`: リポジトリ内のExcelを読み書き（開発・デモ用。Azure AD承認前でも動作確認可能）
  - `graph`: Teams上のExcelを読み書き（本番用）

## 7. 決定事項と残タスク

### 決定済み
- [x] ホスティング先: **Vercel**（無料枠で開始。環境変数でシークレット管理）

### 残タスク（社内確認・運用系）

- [ ] 個人ログイン化のタイミング（データ構造は対応済み。必要になったら個人PIN等に拡張）

## 8. システム構成

```
[スマホブラウザ]
   │ 共通PIN認証（Cookie）
   ▼
[Next.js アプリ（Vercel）]
   │ サーバー側APIルート（PIN検証後のみ）
   │   /api/master /api/members /api/records /api/export
   ▼
[データ層（STORE_MODEで切替）]
   ├─ local: data/inventory.local.xlsx（開発用）
   └─ graph: Microsoft Graph API（client credentials）
              │
              ▼
      [Teams「棚卸しチーム」の inventory.xlsx]
        ├─ 品目マスタ（MasterTable）
        ├─ 棚卸し記録（RecordTable）← アプリが追記/編集/削除
        └─ 入力者（MemberTable）
```

実装の詳細・起動手順は `inventory-app/README.md` を参照。
